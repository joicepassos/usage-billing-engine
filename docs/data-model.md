# Data model

One PostgreSQL 17 database with TimescaleDB, one schema. Each module owns its tables; other modules never query them. Status: approved 2026-11-03. Tables marked *planned* are created by the task shown.

## Conventions
- **Money:** `numeric(18,2)` for invoice amounts; `numeric(20,6)` for unit prices and quantities (ADR 0002).
- **Time:** instants in `timestamptz` (UTC); billing periods as a `date` holding day 1 of the month, computed in `America/Sao_Paulo`.
- **Ids:** UUIDs generated by the application; tenant-chosen ids are `text`.
- **States:** `text` with a `CHECK` listing the values, instead of Postgres enums.
- **Concurrency:** a `version` column for optimistic locking on tables whose state changes.
- **Tenancy:** `tenant_id` with `@TenantId` on every entity; justified exemptions only (ADR 0008). Tables written with plain JDBC pass `tenant_id` explicitly.
- **References across modules:** by id only, no foreign keys (ADR 0001, amendment 1). Foreign keys only inside a module.
- **Personal data (LGPD):** marked *PII* below; never logged, masked in API responses.

## Decisions taken with the data model
| Id | Decision |
|---|---|
| D1 | TimescaleDB unique indexes must include the partitioning column, so idempotency lives in the `ingested_transaction` ledger, written in the same transaction as the event (ADR 0003, amendment 1). |
| D2 | The late-event rule runs at ingestion and the result is stored as `usage_event.billing_period`. The cycle close filters raw events by that column and never depends on aggregate freshness (ADR 0003 and ADR 0004, amendment 1). |
| D3 | No foreign keys across modules (ADR 0001, amendment 1). |
| D4 | The monthly minimum belongs to the plan and is applied to the invoice as an adjustment line. |
| D5 | `unique` metrics count distinct `usage_event.unique_key` values, computed from raw events; continuous aggregates cannot count distinct values. |
| D6 | `fiscal_document.taker_snapshot` keeps a copy of the customer's fiscal data as issued. |
| D7 | Reissuing an NFS-e or a charge creates a new row; partial unique indexes keep one active row per invoice. |
